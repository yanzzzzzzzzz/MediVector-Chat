# 醫療文件知識管理原型操作示範

開啟 http://127.0.0.1:8000/knowledge，使用本機管理員工作空間，選擇「主院區／一般衛教」。

示範資料位於 `examples/education-demo.json`，是參考 CDC、美國心臟協會及美國 VA 公開資訊另寫的合成短篇，未經院所醫療專業審查。系統中的核准僅展示軟體流程，不代表臨床核准。

此示範驗證文件管理、版本審核與引用追溯的工程流程。醫療內容專業審查與真人 Pilot 留待後續實際導入階段，未完成時不宣稱已具臨床使用效力。

## 操作步驟

1. 按「新增文件」，填入標題、版本、來源、網址、適用院區科別、效期、原文、使用依據及建立說明，按「儲存草稿」。
2. 在該版本右側「更多操作」按「送交審核」，填寫原因。狀態變成「待審核」。
3. 具審核權限的帳號可在「審核佇列」查看原文，再選「核准發布」或「退回草稿」，並留下原因。
4. 原文需修改時選「建立新修訂」，填入新的版本名稱與修訂理由，重新送審。核准新版後，舊版成為「已取代」，可從「歷史版本」查看。
5. 點文件標題或「檢視」可核對原文、來源網址與版本 ID。完整事件紀錄另可透過 `GET /api/knowledge/documents/{document_id}/history` 讀取。

本次預覽保留三份文件：洗手步驟 v1.1 已發布（v1.0 已取代）、居家血壓紀錄待審核、門診準備為草稿。

## AI 索引與查詢

沒有設定 `OPENAI_API_KEY` 時仍可管理來源和審核，片段的 embedding 為 NULL，畫面顯示「待建索引」。未完整索引的版本不會進入正式檢索或 corpus manifest。

設定有效 Key 並重新啟動後，可由具權限的帳號在版本「更多操作 → 建立檢索索引」建立真正的 embedding。此操作保留原有片段 ID、原文和校驗碼，留下索引事件；不覆寫既有索引。完成後，經核准、有效且授權的版本才可用於「核准知識查詢」。


## 來源檢查預覽

本機預覽已啟用可選來源檢查。可在「核准知識查詢」依序輸入：

- 「示範洗手文件提到至少搓洗多久？」：核對回答與原文引用。
- 「本院大腸鏡檢查前何時停用藥物？」：即使找到同主題以外的來源，也應保留資訊不足。

[實際驗證結果、啟用與關閉方式](preview-validation.md)。專案預設開關仍為 false，
此本機預覽以額外 Compose 設定啟用，不代表通過醫療內容審查。
