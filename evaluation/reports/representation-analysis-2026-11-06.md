# 原型檢索改善：標題與 PDF 頁碼控制實驗

本輪固定現有兩份合成來源、30 題候選題、`text-embedding-3-small`、distance 上限 0.65、margin 0.12 與 K=5，比較四種 embedding 輸入。查詢改寫全部關閉，同一問題的向量跨組共用，37 個不同輸入各建立一次 embedding。這是實際 API 實驗，不是 mock 結果；標註仍未經人工審查。

## 結果與判斷

| 輸入方式 | 提議可回答題命中 | 暫定證據覆蓋 | 提議無答案題仍返回候選 |
|---|---:|---:|---:|
| 片段正文 | 16/20 | 80% | 3/10 |
| 標題＋正文 | 20/20 | 100% | 2/10 |
| 標題＋頁碼＋正文 | 20/20 | 100% | 2/10 |
| 逐頁分塊，附標題與頁碼 | 20/20 | 95% | 2/10 |

只加入標題，就找回原本漏檢的 016–019，且 030 不再返回候選。本次支持「標題能改善這份樣本的 PDF 漏檢」；不能推論所有 PDF、其他語言或真實院所語料都會改善。頁碼與逐頁切分在文件層級沒有額外命中收益。

逐頁分塊在 020 的證據覆蓋分數較低：候選標註是一段跨頁的完整區間，其中含有合併原文時的空白分隔；逐頁片段未覆蓋分隔字元，依目前嚴格區間聯集指標計為未完整覆蓋。這不是文字被刪除的證據，也不能直接當成逐頁分塊品質下降。後續應核對跨頁 evidence spans 的標註方式。

加入標題後，024（停藥時間）與 028（其他院區規範）仍返回洗手文件，距離約 0.6002 與 0.5879。標題無法完全解決無答案問題。這是檢索誤命中；本實驗沒有生成答案，不能宣稱出現或消除了幻覺。

## 實作邊界

新增 `evaluation.representation_comparison`，在記憶體中用 exact cosine 排序，再套用既有 `filter_references`。不讀寫線上資料庫、不重建正式索引、不改線上門檻。只改 embedding 輸入的實驗表示，原文、checksum、版本、頁碼與引用 offset 保留。

報告保持 `verified_baseline=false`、`release_gate_eligible=false`，不填人工 reviewer，不改既有待審題目。輸出保存每種表示法、實際距離、逐題排名與程式雜湊；未保存向量，重跑外部模型仍可能有微小數值差異。

## 後續工程順序

1. 擴充合成／授權文件，加入相近標題、相似主題、長文件與中英文內容，搭配不直接提及標題的新題目，檢查標題增益是否能泛化。
2. 在隔離實驗索引驗證標題＋正文；若採用，必須記錄 embedding 表示法版本，明確重建索引，避免新舊表示混用。此次未將小樣本結果直接套入正式索引。
3. 對無答案與誤命中案例比較後續相關性判斷策略，記錄額外延遲／成本及誤拒率；先保留現有無證據回答邊界。

## 驗證與產物

新增 7 個測試，涵蓋原文位置、空白頁跳過、來源／版本一致性、共用查詢向量、錯誤向量及禁止混入人工審查狀態。完整後端測試發現 100 項，70 項通過，30 項需 PostgreSQL 的整合測試略過；此次未執行資料庫整合測試。測試時以 `API_USERS={}` 與空的 `RETRIEVAL_API_TOKEN` 隔離本機 `.env` 授權設定。
