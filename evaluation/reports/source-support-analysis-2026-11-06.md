## 判斷方式

模型先列出問題要求的各項資訊，再逐項標示 supported、missing 或 uncertain。supported 必須附上來源片段 ID 與逐字原文，程式確認該 ID 在本次候選中、引文確實存在，並由程式推導整體結果。

- 全部資訊 supported 才估計為 sufficient。
- 部分有支持、部分缺少資訊為 partial；有任何不確定則保留 uncertain。
- 引文不存在、來源 ID 錯誤、格式不完整或模型請求失敗，都不接受，不以另一個答案補救。
- 空來源不呼叫判斷模型。超過題目／來源預算時不截斷文字，而保留不確定。

逐字引文校驗只能確認引用位置，不能證明推論正確，也不能保證模型完整拆解所有問題。報告與 API 均保留 `human_reviewed=false`、`semantic_support_verified=false`。

## 可選的問答流程

設定 `SOURCE_SUPPORT_CHECK_ENABLED=true` 並重新啟動服務，可在院所帳號的 `/api/ask` 啟用。預設為 false；本輪沒有修改本機 `.env`、重啟預覽或重建正式索引。

啟用時使用已通過原有院區／科別、狀態、效期與 ACL 過濾的片段，並以既有檢索流程產生的 standalone question 檢查來源。個人 legacy 聊天不受此開關影響。

未通過時直接回覆資訊不足並請向文件負責人確認，不呼叫答案模型；保留候選參考方便核對。通過時只將逐字引文對應的候選片段交給答案模型，保留原引用編號。這個開關不會改善第一階段漏檢，也不會自動替正式索引加入標題；本次 36/36 的結果不能直接套用為線上效果。

API 與歷史訊息只保存 `source_support_assessment` 摘要，不另存模型需求拆解與引文副本。稽核快照包含開關、提示版本雜湊、估計摘要，以及答案模型是否實際被呼叫。既有撤回／權限變動後的歷史遮蔽仍適用。
